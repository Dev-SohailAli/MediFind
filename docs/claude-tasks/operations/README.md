# Pilot operations and release task queue

This queue begins only after the protected-pilot tasks have passed their
provider, legal, privacy, security and recovery gates. It turns approved
features into a small, founder-operated Suva pilot. Each task requires
synthetic rehearsal before real activation.

| Task | Brief | Gate |
| --- | --- | --- |
| 16 | [Pharmacy onboarding and activation](task-16-pharmacy-onboarding-activation.md) | Protected workflows and training content approved |
| 17 | [Hours, freshness and reconciliation](task-17-hours-freshness-reconciliation.md) | Branch/listing schema and business-time rules |
| 18 | [Backup, restore and deletion](task-18-backup-restore-deletion.md) | Data classification, retention and provider evidence |
| 19 | [Cost breakers and kill switches](task-19-cost-breakers-kill-switches.md) | Approved budget and founder re-enable path |
| 20 | [Incident exercises and operations privacy](task-20-incident-exercises-operations.md) | Incident owner and synthetic exercise plan |
| 21 | [Performance, accessibility and beta acceptance](task-21-performance-accessibility-beta.md) | Stable protected flows and test devices/networks |
| 22 | [Staged release and rollback](task-22-staged-release-rollback.md) | All prior evidence and named owner |

No task authorizes production release by itself.

After Task 22, continue only through the gated [post-pilot growth
queue](../post-pilot/README.md). A staged release is evidence for review, not
permission for unrestricted public growth, billing or a new provider.
